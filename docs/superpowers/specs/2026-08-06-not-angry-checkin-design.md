# 不生气打卡小程序 — 设计文档

**日期：** 2026-08-06
**状态：** 已确认

## 1. 概述

一款微信小程序，帮助用户培养"不生气"的习惯。

- **早上**：用户开启当日挑战，承诺今天不生气。
- **晚上**：用户确认今天确实没有生气，当日挑战成功。
- **统计**：连续未生气天数、累计天数、最多连续天数。
- **成就**：连续打卡达到 3 / 7 / 14 / 30 / 100 天时解锁里程碑徽章。

## 2. 约束与决策

| 项目 | 决策 |
|------|------|
| 平台 | 微信小程序（原生 WXML/WXSS/JS） |
| 存储 | 本地存储 `wx.setStorageSync`，单用户 |
| 提醒 | 无定时推送（不引入订阅消息） |
| 打卡流程 | 早设定 + 晚确认，二者都完成才计入成功 |
| 技术栈 | 原生微信小程序，无第三方依赖 |

## 3. 页面结构

### 3.1 pages/checkin（今日打卡，Tab 1）

- 顶部：当前日期 + 当日状态文案。
- 主状态区：
  - 未设定：按钮【开启今日挑战】。
  - 已设定未确认：提示"已承诺，期待今晚好消息"。
  - 已确认：完成动效 + "今日挑战成功"。
- 底部：当前连续天数大数字展示。

### 3.2 pages/stats（统计与成就，Tab 2）

- 统计卡：连续天数 / 累计天数 / 最多连续天数。
- 成就徽章网格：3 / 7 / 14 / 30 / 100 天。已解锁为彩色，未解锁为灰色锁定。

## 4. 数据存储

storage key：`checkin_records`

```
[
  { "date": "2026-08-06", "done": true },
  { "date": "2026-08-05", "done": true }
]
```

- `date` 为 `YYYY-MM-DD` 字符串。
- `done` 为 true 表示当日挑战成功。
- 未设定 / 已设定未确认不写入，或仅写入 `{ date, started }`（设计上从简：只在确认成功后写入 `done:true`；设定动作记录为 `started:true`，跨天清理）。

> 简化决策：**仅存储成功记录**（`done: true`）。"已设定但未确认"的状态保存在内存中（页面 onShow 时判断当天记录即可推导），无需持久化中间态，减少存储复杂度。

## 5. 核心逻辑

### 5.1 当日状态推导（utils/date.js + utils/store.js）

给定今天日期 `today`：

- 记录中存在 `today` 且 `done === true` → **已完成（成功）**。
- 否则 → **未完成**（含未设定与已设定未确认）。

### 5.2 天数统计（utils/store.js `computeStats`）

对 `checkin_records` 按日期升序排序去重：

- **累计天数**：`done === true` 的记录条数。
- **连续天数**：从今天（或昨天）往回数连续 `done === true` 的天数。
  - 若今天已 `done`，从今天开始计数；否则从昨天开始计数（今天还没确认，昨天若成功则连续天数延续）。
  - 若昨天也不成功，则连续天数为 0（今天未确认）或 1（今天已确认）。
- **最多连续天数**：遍历历史，计算过的最长连续成功段。

### 5.3 成就判定（utils/achievements.js）

里程碑定义：

```js
const MILESTONES = [3, 7, 14, 30, 100];
```

判定规则：以**当前连续天数**为基准，达到某里程碑时解锁。解锁后本地标记（storage key：`unlocked_achievements`，数组存已解锁的里程碑值），再次达到不重复弹提示。

## 6. 页面数据流

- `app.js`：全局无状态，仅做生命周期。
- `pages/checkin`：`onShow` 时调用 `store.getTodayStatus()` 与 `store.computeStats()` 刷新；点击【开启今日挑战】→ 写 `started` 标记；点击【今晚确认】→ 写 `done:true`，调 `achievements.checkAndUnlock(连续天数)`，若解锁则弹成就提示。
- `pages/stats`：`onShow` 时调用 `store.computeStats()` 与 `achievements.getAll()` 渲染统计卡与徽章网格。

## 7. 错误处理与边界

- storage 读取失败或数据损坏（非数组）时，视为空数据并重置。
- 同一日期重复确认：幂等，不重复计数。
- 跨天切换：页面 `onShow` 每次重新计算，天然按自然日切分。
- 日期计算使用本地时区，避免 UTC 偏移导致跨天错误。

## 8. 测试

由于是微信小程序，无自动化测试框架。验证方式为手动测试清单：

1. 首次进入 → 未设定状态，连续天数 0。
2. 开启今日挑战 → 显示已设定状态。
3. 今晚确认 → 连续天数变 1，累计 1。
4. 次日确认 → 连续 2。
5. 隔一天不确认 → 连续归零，但累计保留。
6. 连续达 3 / 7 天 → 成就徽章解锁并弹提示。
7. 成就再次达到同一里程碑 → 不重复弹提示。
